# UI/UX 设计规范

> 版本：V0.1｜状态：草案｜方向：Q 版暗黑幻想、欧美卡通、轻魔幻

## 1. 体验原则

1. 战斗始终是视觉焦点，成长入口服务于快速回到战斗。
2. 一次操作只表达一个主要结果；重要资源消费必须可预期。
3. 数值层级清晰：当前值、变化值、可升级状态不可混淆。
4. 红点只表示“现在可处理”，不能永久常亮或诱导无效点击。
5. 触控目标不小于 80×80 设计像素，并适配微信安全区。

## 2. 信息架构

```text
启动/开始
└── 主城
    ├── 战斗（核心）
    ├── 英雄
    ├── 装备
    ├── 背包
    ├── 任务/成就
    ├── 图鉴
    ├── 商店
    └── 设置
```

战斗、英雄、装备、背包、任务采用持久主导航。返回行为必须可预测：弹窗先关闭，二级页返回来源页，主页面返回不退出游戏。

## 3. 战斗页布局

- 顶部：章节/关卡、金币、钻石、设置。
- 中部：怪物、生命条、状态、伤害反馈与战斗舞台。
- 下部：主角与英雄、升级提示、4 个主动技能。
- Boss：倒计时置于生命条附近，狂暴阶段使用颜色和音效双重提示。

战斗舞台可点击区域与 UI 控件必须互斥。连续点击反馈应轻量，伤害数字合并或限流，避免遮挡 Boss 动作。

## 4. 通用组件

按钮状态包含默认、按下、禁用、加载；禁用时必须说明条件。弹窗统一包含标题、内容、主操作、次操作和关闭方式。奖励展示统一使用“图标 + 名称 + 数量”，稀有奖励允许强化动效。

资源不足弹窗优先引导可玩的获取途径，不直接跳转付费。广告按钮明确标注奖励与次数，例如“观看广告，金币 ×2（1/3）”。

## 5. 视觉基线

- 主背景：低明度蓝灰/紫黑；交互高亮：暖金；危险：暗红。
- 品质色必须同时配合边框或标签，不能仅靠颜色区分。
- 标题、正文、数字至少建立三级字号；核心战力和奖励数字优先。
- 禁止在同一页面混用多套描边、阴影和按钮形状。
- 图标按功能、资源、装备、技能四套语义体系维护。

## 6. 动效与音效反馈

普通反馈 100～200ms，页面切换 200～350ms，稀有奖励不超过 1.5s 且可跳过。点击、升级、装备替换、Boss 出场和胜利需要独立反馈。设置中的音乐、音效和震动开关即时生效并写入存档。

## 7. 原型交付与验收

每页原型必须包含默认、空、加载、资源不足、成功和异常状态；标注入口、出口、触发条件、数据字段、红点规则和埋点预留。设计稿需提供目标分辨率、安全区、九宫格拉伸和多语言扩展空间。

设计分辨率固定为 750 × 1334 竖屏，缩放策略采用 `FIXED_WIDTH`：始终完整保留 750 设计宽度，按设备比例扩展可见高度。背景允许延伸到屏幕边缘；文字、按钮等交互内容必须位于 Cocos `SafeArea` 容器内，由 `sys.getSafeAreaRect()` 统一适配 iOS、Android 和微信小游戏的刘海、状态栏及底部手势区。页面不得自行读取平台安全区数据。
