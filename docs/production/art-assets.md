# 美术资源清单与交付规范

> 版本：V0.1｜状态：盘点草案｜MVP 范围

## 1. 美术方向

整体采用 Q 版暗黑幻想：约 2.5 头身、欧美卡通造型、清晰剪影、鲜明技能色。背景使用 2D 分层，英雄优先 Spine 骨骼动画，怪物根据成本选择 Spine 或序列帧。

## 2. MVP 资源台账

| 类别 | 数量 | 最低动作/状态 | 优先级 |
| --- | ---: | --- | --- |
| 主角与英雄 | 8 | 待机、攻击、受击、技能、胜利 | P0 |
| 普通怪物 | 20 | 待机、攻击、受击、死亡 | P0 |
| Boss | 5 | 待机、攻击、受击、死亡、2～3 技能、狂暴 | P0 |
| 章节背景 | 1 套首发 | 远景、中景、近景、地面、氛围层 | P0 |
| 装备图标 | 100+ | 7 部位、品质边框可复用 | P1 |
| 技能图标 | 20 | 普通、禁用、冷却遮罩适配 | P1 |
| UI 页面 | 10 | 页面底图、面板、按钮、标签 | P0 |
| 战斗特效 | 20+ | 命中、暴击、技能、Boss 预警 | P0 |
| 音频 | 30+ | BGM、UI、战斗、技能、奖励 | P1 |

## 3. 命名规范

```text
hero_<id>_<action>
monster_<id>_<action>
boss_<id>_<action>
equip_<slot>_<templateId>
skill_<id>_icon
vfx_<system>_<effect>
ui_<page>_<element>_<state>
sfx_<system>_<event>
bgm_<scene>
```

全部使用小写英文、数字和下划线；业务 ID 必须与 JSON 配置一致。禁止使用“最终版”“新版2”等不可追踪名称。

## 4. 技术交付

- 原始工程文件与导出文件分开保存，保留字体、插件和版本说明。
- UI 提供正常、按下、禁用和选中状态；可拉伸面板标注九宫格。
- Spine 统一骨骼缩放、原点、朝向、插槽命名和导出版本。
- 序列帧统一帧率、画布尺寸和原点，删除透明冗余但不改变锚点。
- 纹理使用合理图集，透明素材预乘规则保持一致。
- 音频标注循环点、响度类别和压缩格式；短音效避免尾部静音。

具体尺寸、压缩格式和图集上限必须在 Cocos Creator 3.8.8 中完成首轮微信真机测试后确定。资源导入后必须保留 Creator 生成的 `.meta` 文件，移动或重命名资源应通过编辑器完成，避免 UUID 引用失效。

## 5. 验收标准

资源须在目标场景中验收，而非只查看源文件。检查剪影辨识、技能读条、受击方向、Boss 预警、低端机性能、压缩瑕疵和内存释放。每项资源在台账中记录负责人、状态、源文件、导出路径、关联配置 ID 和验收日期。

## 6. 生产优先级

先用灰盒完成战斗与 UI 流程，再依次替换：主角/首只怪物 → 首个 Boss → 通用 UI → 8 英雄 → 20 怪物 → 装备和技能图标 → 完整特效与音频。避免在公式和交互未验证前批量生产资源。
