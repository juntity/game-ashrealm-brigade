# AI 开发手册

> 版本：V0.1｜适用：Codex、Claude Code、GPT 类编码代理

## 1. 使用原则

AI 每次只处理一个边界清晰、可验证的任务。输入必须包含需求来源、允许修改的目录、数据契约、验收标准和验证命令。禁止让 AI 根据概述性 GDD 一次生成整个游戏。

优先级为：已批准专项文档 → 接口与配置 Schema → 测试 → 实现。遇到 `TBD`、文档冲突或影响存档的数据变更时必须停止猜测，提交问题清单。

## 2. 标准任务模板

```text
任务：<一个可交付结果>
需求依据：docs/...（注明章节）
允许修改：<目录或文件>
禁止修改：<公共接口/配置/场景>
输入契约：<类型、事件、配置字段>
验收标准：
1. <可观察结果>
2. <边界/异常结果>
验证命令：<lint/test/build>
交付要求：列出修改文件、设计决策、测试结果、剩余风险
```

## 3. 模块 Prompt 示例

```text
实现纯 TypeScript DamageCalculator，不依赖 Cocos Creator 的 `Node` 或 `Component`。
依据 docs/technical/tdd.md 与 docs/balance/numerical-design.md。
输入包含攻击、技能倍率、暴击参数和增伤乘区；输出伤害值及是否暴击。
使用注入的随机源，禁止调用 Math.random；明确取整时点。
先写正常、必暴击、零倍率和边界值测试，再实现。
不要修改 UI、配置结构或存档。
```

## 4. 推荐开发顺序

1. 初始化工程、代码规范、测试与配置校验。
2. 纯逻辑：属性、伤害、关卡、奖励和时间。
3. 存档 Schema、迁移、备份和幂等奖励。
4. Battle 灰盒闭环。
5. Hero、Skill、Equip/Bag、Task。
6. UI 页面、广告适配、音频和正式资源。
7. 配置填充、数值模拟、真机优化和发布检查。

## 5. 代码约束

- 业务逻辑不得依赖 Creator 场景、`Node`、`Component` 或节点查找。
- 禁止跨模块直接写状态，禁止新增全局单例绕过服务接口。
- 随机、时间、存储和广告必须可注入或通过适配器访问。
- 新配置字段必须补类型、默认值、校验和迁移说明。
- 修改奖励或消费逻辑必须包含重复调用测试。
- 不提交密钥、构建产物、临时资源或未经说明的大文件。

## 6. AI 交付检查

审查者必须确认：实现对应批准需求；未扩大范围；错误和取消路径可恢复；事件监听、调度器和 Tween 被清理；存档向后兼容；配置引用可校验；测试真实覆盖验收条件；Creator 组件生命周期使用正确；业务层未直接调用 `wx.*`。

AI 的“已完成”不等于任务完成。只有代码审查、自动测试、编辑器运行和目标微信设备验证均通过后，任务才能标记为完成。

## 7. 上下文包

给 AI 的最小上下文应包括 `AGENTS.md`、相关专项文档章节、目标模块接口、配置样例和邻近测试。不要一次注入全部文档；只提供当前任务所需事实，并要求 AI 在交付中引用其依据。
