# MVP 研发计划与任务拆解

> 版本：V0.1｜状态：草案｜目标周期：4～6 周

## 1. 里程碑

| 阶段 | 目标 | 退出条件 |
| --- | --- | --- |
| M0 立项基线 | 锁定范围与技术基线 | PRD/TDD 评审，Creator 3.8.8 与屏幕方向确认 |
| M1 可玩灰盒 | 完成核心战斗循环 | 自动攻击、点击、普通怪、Boss、金币、升级可连续运行 |
| M2 成长闭环 | 完成主要系统 | 英雄、技能、装备、背包、任务、离线收益接入存档 |
| M3 内容整合 | 填充首章内容 | 100 关、8 英雄、20 怪、5 Boss、资源和配置通过校验 |
| M4 发布候选 | 微信真机可发布 | 无阻断缺陷，性能、存档、广告和合规检查通过 |

## 2. 工作分解

### M0：工程与规范

- 使用已锁定的 Cocos Creator 3.8.8 和微信基础库最低兼容版本 2.12.0，确定竖/横屏。
- 使用 2D 项目模板初始化工程，并验证浏览器预览与微信小游戏构建。
- 创建工程目录、TypeScript 严格模式、格式化、测试和 CI。
- 定义配置 Schema、ID 规范、错误日志和开发作弊面板。
- 批准 PRD 的 4 个 `TBD` 与数值目标。

### M1：核心战斗

- 实现时间服务、随机源、属性聚合和伤害计算器。
- 实现战斗状态机、自动攻击、点击攻击、怪物刷新和 Boss 计时。
- 实现关卡配置加载、胜负结算、金币奖励与英雄升级。
- 用灰盒资源完成首关、首个 Boss 和页面往返恢复。

### M2：成长系统

- 英雄解锁、阵容、批量升级和属性展示。
- 主动/被动技能、装配、冷却和效果。
- 装备实例、词条、穿戴、强化、升星、分解和出售。
- 背包筛选/保护、任务/成就、离线收益和广告适配。
- 存档备份、版本迁移、跨天刷新与重复奖励保护。

### M3：内容与表现

- 填充并校验 100 关、怪物、Boss、英雄、技能和掉落配置。
- 接入正式 UI、Spine/序列帧、特效、音频和图集。
- 运行数值模拟，完成首轮全流程试玩与两轮平衡调整。
- 完成图鉴、设置及 MVP 商店范围。

### M4：质量与发布

- 覆盖冷启动、异常退出、前后台、跨天、存档损坏和广告失败。
- 在目标设备验证 FPS、内存、首包/分包、加载和发热。
- 检查隐私、广告、版本信息、错误上报和发布配置。
- 冻结 RC 配置，完成 1～100 关回归并建立已知问题列表。

## 3. 优先级与依赖

`P0` 是核心循环、数据安全和发布阻断项；`P1` 是 MVP 完整体验；`P2` 可推迟到 V1.1。配置 Schema 先于内容填充，纯逻辑先于正式表现，存档契约先于大规模功能接入，美术批量生产先经过灰盒验证。

## 4. 完成定义（DoD）

每个任务必须满足：

- 需求与验收标准明确，不包含未批准扩展。
- 代码通过格式化、类型检查、测试和配置校验。
- 正常、失败、取消、重复调用和恢复路径已验证。
- 影响存档或配置时提供迁移/兼容说明。
- UI 功能在 Cocos Creator 和至少一台微信目标设备验证。
- 文档、配置样例和变更记录同步更新。

## 5. 立项前必须决策

1. 游戏屏幕方向与设计分辨率。
2. 首章 Boss 分布与“5 个 Boss/每 10 关 Boss”的统一口径。
3. MVP 商店、钻石和广告每日上限。
4. 首章目标通关时长、背包容量和装备强化规则。
5. 测试框架、CI、首包体积和最低性能设备。
